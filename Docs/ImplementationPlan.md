# 実装計画 — ブラウザパチンコ「FableCatgirlPachi」

Docs/Plan.md のゴールを実現するための実装計画。
`Docs/pachi.png`(盤面画像)と `Docs/character.png`(キャラクター)を素材として、
ブラウザ上でプレイできるパチンコゲームを構築する。

## 技術スタック

| 領域 | 採用技術 | 理由 |
|------|----------|------|
| 言語 | TypeScript (strict) | 要件指定 |
| ビルド | Vite | TS + 静的アセットの開発サーバ・バンドルが最速で構築できる |
| 描画 | PixiJS v8 (WebGL) | WebGL 要件を満たしつつ 2D スプライト・大量オブジェクト描画に最適 |
| 物理 | Rapier2D (`@dimforge/rapier2d-compat`) | WASM で高速。CCD(連続衝突検出)内蔵で「小さく速い玉が釘をすり抜ける」問題を回避できる |
| 状態保存 | localStorage + JSON ファイル入出力 | エディットした盤面レイアウトの保存・共有用 |

※ 物理エンジンの代替候補は Matter.js(API が簡単)だが、パチンコは高速な小球 × 多数の釘という
CCD が効く典型ケースなので Rapier を第一候補とする。

## 座標系と盤面の扱い

- 盤面のワールド座標は `pachi.png` のピクセル座標を基準にした論理座標(幅 1129 基準)で統一。
  物理エンジン内はメートル系にスケール変換(例: 100px = 1m)。
- `pachi.png` は背景スプライトとして描画し、その上に釘・壁・入賞口などの
  物理オブジェクトを配置する。初期配置はエディットモードで画像に合わせて調整する
  (= エディット機能を先に作ると盤面調整が楽になるため、フェーズを前倒しする)。
- 描画(Pixi)と物理(Rapier)は「物理が正、描画は毎フレーム同期」の一方向データフロー。

## 盤面レイアウトの JSON スキーマ(エディット機能の中核)

```jsonc
{
  "version": 1,
  "board": { "width": 1129, "height": 1424 },
  "objects": [
    { "id": "n1",  "type": "nail",     "x": 420, "y": 300, "radius": 5 },
    { "id": "w1",  "type": "wall",     "points": [[0,0],[0,1424]] },
    { "id": "wm1", "type": "windmill", "x": 300, "y": 700, "radius": 24, "speed": 3 },
    { "id": "p1",  "type": "pocket",   "x": 560, "y": 1080, "width": 40,
      "role": "start" },   // role: start | attacker | out
    { "id": "l1",  "type": "launcher", "x": 1080, "y": 1380, "angle": -80 }
  ]
}
```

エディタはこの JSON を編集する UI であり、ゲームはこの JSON から盤面を構築する。
両モードが同一データを共有することで整合性を保つ。

## 実装フェーズ(フェーズごとに commit)

### Phase 0: プロジェクト基盤
- Vite + TypeScript + PixiJS + Rapier2D のセットアップ
- `pachi.png` を背景に表示し、ゲームループ(物理 step + 描画同期)が回る状態
- **完了条件**: ブラウザで盤面画像が表示され、テスト用の玉が重力で落ちる

### Phase 1: 物理盤面と玉の発射
- 外周壁・ガイドレール(玉が盤面上部へ回り込む経路)を構築
- Launcher 実装: ハンドル(スライダー or マウス長押し)で発射強度を調整して発射
- 釘を仮配置し、玉が釘に弾かれて落ちることを確認(CCD 有効化)
- 画面外/こぼれ口に落ちた玉の消滅・回収
- **完了条件**: 発射 → 釘に弾かれる → 下部で回収、の一連の流れが安定動作(60fps・玉50個同時)

### Phase 2: エディット機能 ★前倒し
- モード切替(プレイ ⇄ エディット)
- オブジェクトの選択・ドラッグ移動・追加(パレットから釘/壁/風車/入賞口)・削除
- プロパティ編集(半径・角度・回転速度・入賞口の役割)
- レイアウトの localStorage 自動保存、JSON エクスポート/インポート
- このエディタを使って `pachi.png` の絵柄に合わせた `default.json` を作成
- **完了条件**: エディタで盤面を調整・保存し、リロード後も反映される

### Phase 3: ゲームロジック(抽選・大当り)
- スタートチャッカー入賞 → 1/199 抽選 → 図柄変動演出 → 当落表示
- 保留玉(最大4)の管理
- 大当り時: アタッカー開放(ラウンド制、例: 10R × 開放中の入賞で払い出し)
- 持ち玉管理: 初期持ち玉、発射で減算、入賞で払い出し加算
- **完了条件**: 入賞 → 抽選 → 大当り → 出玉増加、のゲームサイクルが成立

### Phase 4: 自動プレイ機能
- 自動発射(発射強度を維持して一定間隔で連続発射)
- 停止条件の指定: 「指定玉数を打ち切るまで」/「指定時間が経過するまで」/持ち玉0
- 実行中の統計表示(発射数・スタート入賞数・大当り回数・差玉)
- **完了条件**: 「1000発 or 10分」を指定して放置すると自動で打ち続け、条件到達で停止する

### Phase 5: 演出・仕上げ
- `character.png` を使った図柄変動・リーチ・大当り演出(ハート/LUCKY 表示に合わせる)
- ライト点滅・玉の入賞エフェクトなどの視覚演出(Pixi のフィルタ/パーティクル)
- パフォーマンス調整(スリープ設定、オブジェクトプール)、README 整備
- **完了条件**: 一通りのプレイ体験が演出込みで成立する

## コミット方針

Docs/Plan.md の指示どおり、上記フェーズ単位を基本とし、フェーズ内でも独立した機能
(例: Phase 2 の「ドラッグ移動」と「JSON 入出力」)ごとに commit を分ける。

## リスクと対策

- **玉のすり抜け(トンネリング)**: Rapier の CCD を玉に有効化。物理 step は固定 Δt(1/120s × サブステップ)。
- **釘配置の手間**: Phase 2 のエディタを前倒しして解決。画像を下敷きに GUI で配置する。
- **Rapier の WASM 初期化**: `rapier2d-compat` を使い、`await RAPIER.init()` を main で待つ構成にする。
- **多玉時の描画負荷**: Pixi の ParticleContainer / スプライト再利用で対応。
