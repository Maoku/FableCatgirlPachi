# 実装計画 — 動画による演出効果(Docs/MOVIE_PLAN.md 対応)

`movie/` に用意された 4 本の動画を、抽選中(図柄変動)と大当たりの演出に組み込む。
それぞれ 2 本のうちどちらかをランダムで再生する。

## 素材の仕様(確認済み)

| ファイル | 用途 | 解像度 | 長さ | 音声 | サイズ |
|----------|------|--------|------|------|--------|
| loco00.mp4 | 抽選中 | 1920×1080 | 約1.8秒 | AAC あり | 3.4MB |
| loco01.mp4 | 抽選中 | 1920×1080 | 約2.5秒 | AAC あり | 5.6MB |
| atari00.mp4 | 大当たり | 1920×1080 | 約2.9秒 | AAC あり | 5.3MB |
| atari01.mp4 | 大当たり | 1920×1080 | 約3.2秒 | AAC あり | 6.6MB |

計画に影響するポイント:

- **すべて横長 16:9**。盤面(1129×1424 縦長)の液晶エリアに 16:9 の枠を切って表示する。
- **動画は数秒と短い**。抽選(変動 2.4〜4.2 秒+)や大当り(数十秒)より短いため、**ループ再生**が前提。
- **音声トラックあり**。ブラウザの自動再生ポリシー上、無操作でのミュート解除再生はブロックされ得るため、**ミュート再生を既定**とする(対策は後述)。
- **合計約 21MB**。起動時に全読込を待つとローディングが長くなるため、起動をブロックしない先読みにする。

## 表示位置とレイヤ構成

現在の演出は `EffectsLayer` が液晶部分(リール中心: x=562, y=520)に描画している。
動画は同じ液晶エリアに **リール・バナー等の背面** として重ねる。

```
背景(pachi.png) → LED → 盤面オブジェクト → 玉 → EffectsLayer
                                                  ├── 動画スプライト(新設・最背面)★
                                                  ├── リール枠 + 図柄
                                                  └── 大当り演出(キャラ・ハート・バナー)
```

- 表示枠はリール枠を覆う 16:9 矩形(例: 幅 640 × 高さ 360、中心はリールに合わせる)。
  角丸マスク + 枠線で既存のリール枠と統一感を出す。実寸は盤面画像に合わせて実装時に調整。
- 図柄・「リーチ!」・「ROUND n/10」・BONUS バナーは従来どおり動画の上に表示する
  (当落情報が動画で隠れないようにするため)。

## 実装方式

### 新設: `src/fx/MoviePlayer.ts`

HTMLVideoElement と PixiJS v8 の VideoSource テクスチャをラップするクラス。

```ts
class MoviePlayer {
  // 4本ぶんの <video> 要素とテクスチャを保持(生成は1回、再利用する)
  preload(): void;                       // 起動後に preload='auto' で先読み(起動はブロックしない)
  play(kind: 'loco' | 'atari'): void;    // 2本からランダムに選び、先頭から再生して表示(loco はループ、atari は1回のみ)
  stop(): void;                          // 一時停止して非表示(pause + currentTime リセット)
  readonly view: Container;              // EffectsLayer に addChild する表示ノード
}
```

設計上の要点:

- `<video>` は `muted` / `playsInline` / `loop` を設定。iOS Safari(スマホ縦持ち対応済みのため必須)
  でインライン自動再生を成立させる。
- `Texture`(VideoSource)は動画ごとに 1 度だけ生成して再利用。再生のたびに
  `currentTime = 0` に巻き戻す。非再生時は `pause()` して描画・電池消費を抑える。
- `play()` が動画ロード失敗・未ロードでも例外にしない(**動画なしでも既存演出だけで成立**する
  グレースフルデグラデーション)。

### 組み込み(既存コードへの変更点)

| ファイル | 変更内容 |
|----------|----------|
| `movie/*.mp4` | `public/assets/movie/` へ `git mv`(Vite がそのまま配信・ビルドコピーする置き場所。既存の `assets/pachi.png` と同じ相対パス規約で GitHub Pages でも動く) |
| `src/fx/EffectsLayer.ts` | `MoviePlayer` を保持し最背面に追加。`startSpin()` で `play('loco')`、変動終了(`onDone` 呼び出し時)に `stop()`。`celebrate()` で `play('atari')`(1回再生、動画の `ended` で自動停止)。既存の告知演出時間 `CELEBRATE_TIME`(2.4秒)を動画の長さ(約3.2秒)に合わせて延長。`reset()` で `stop()`(エディットモード遷移対策) |
| `src/core/Game.ts` | 変更不要(atari は告知時のみで、ボーナス進行との連動がないため) |
| `src/main.ts` | boot 完了後に `preload()` を呼ぶ(初期表示をブロックしない) |

### 再生タイミングの仕様

- **抽選中(loco)**: 図柄変動の開始〜当落表示の終了までループ再生。
  変動のたびにランダムで選び直す。リーチ時も同じ動画を流し続ける(将来リーチ専用に
  差し替えたくなった場合に備えて `play()` の引数は種別で受ける)。
- **大当たり(atari)**: **当り告知(`celebrate()`)時のみ** ランダムで 1 本を 1 回再生する
  (ループなし、動画終了で停止・非表示)。告知演出の長さは動画(約 2.9〜3.2 秒)に合わせて
  延長する。ボーナスのラウンド消化中は動画を流さず、従来の ROUND 表示のみ。
- エディットモードへの切替(`reset()`)では即停止・非表示。

### 音声の扱い

既定はミュート(自動再生ポリシーでブロックされない唯一の安全な形)。
ただしゲーム操作(ハンドル・ボタン)で必ずユーザージェスチャが発生するため、
**初回 pointerdown で `muted = false` を試みる「音声アンロック」** を任意対応として Phase 3 に置く。
HUD に 🔊/🔇 トグルを追加し、設定は localStorage に保存する。

## 実装フェーズ(フェーズごとに commit)

### Phase 1: MoviePlayer とアセット移設
- `movie/*.mp4` を `public/assets/movie/` へ移動
- `MoviePlayer` 実装(ロード・ランダム選択・ループ・停止・失敗時フォールバック)
- **完了条件**: デバッグ用ハンドル(`__fcp`)から `play('loco')` / `play('atari')` を呼ぶと液晶エリアで動画がループ再生・停止できる

### Phase 2: 演出への接続
- 抽選中: `startSpin` 〜 当落表示終了に連動
- 大当たり: `celebrate` 〜 ボーナス終了に連動
- エディットモード遷移で停止
- **完了条件**: 通常変動・ガセリーチ・大当り(告知→10R→終了)の一連で動画が仕様どおり切り替わる。動画ファイルが読めない環境でも従来演出のみで動作する

### Phase 3: 仕上げ(モバイル・音声・性能)
- スマホ縦持ちレイアウトでの表示確認(playsInline)
- 音声アンロック + HUD のミュートトグル(任意)
- 先読みタイミング調整・README 追記
- **完了条件**: PC / スマホ想定サイズの両方で演出が成立し、起動時間が悪化していない

## 検証方法

抽選は 1/199 なので、検証時は `__fcp` デバッグハンドル経由で強制的に当りを発生させる
(例: コンソールから `__fcp.game` の抽選を直接叩く、または一時的に確率を上げて自動プレイ)。
ブラウザプレビューで以下を確認する:

1. 変動開始で loco のどちらかが再生され、複数回の変動でランダムに切り替わること
2. 当落表示後に動画が止まり、非表示になること
3. 大当りの告知時に atari が 1 回再生され、動画終了で止まること(ラウンド消化中は流れないこと)
4. エディットモード切替で即停止すること
5. コンソールに自動再生ブロック等のエラーが出ないこと

## リスクと対策

- **自動再生ブロック(特に iOS)**: `muted` + `playsInline` を必須設定。音声は任意機能として分離。
- **初回再生時のカクつき**: 起動直後にバックグラウンドで `preload='auto'`。読み込み未完了で
  再生要求が来た場合もそのまま `play()` し、ブラウザのストリーミング再生に任せる。
- **リポジトリ/配信サイズ増(+21MB)**: GitHub Pages の制限(1GB)には遠く及ばないため許容。
  将来問題になったら 720p への再エンコードで半減できる。
- **WebGL テクスチャ更新負荷**: 再生中のみ VideoSource を有効化し、停止中は `pause()` +
  非表示でアップロードを止める。
